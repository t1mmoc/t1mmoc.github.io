如果我说，一个只会写代码、不会画一张图、不会写一段旋律的人，用**两天半**时间，从零做出一款能联网对战的桌游——你大概会觉得我在吹牛。

但这是真的。更关键的是：我没有雇人，没有外包，背后是一支「AI 工作室」——一个 WorkBuddy Agent，在我这个「创意总监 + 终审」的指挥下，分饰 PM、前端、后端、规则设计师、美术、音效、DevOps 八个角色。

下面是这份「两天半造一家游戏工作室」的完整复盘。

## 一、先上硬核数据

- **两天半** · 1 个人 · 1 个 WorkBuddy · **130 次提交** · **5 个仓库**
- **9.5 千行核心源码** · **74 个单元测试全绿** · **4 张地图** · **173 张美术贴图** · **30 个音效**
- **8 大管线一人包揽**：前端 / 后端 / 规则引擎 / 地图编辑器 / 美术 / 音效 / CI·CD / 文档

（游戏叫《烽决》，一款军棋变体的双人——同屏 / 联机——战棋桌游。先记住名字，文末有试玩。）

## 二、为什么做这件事

两个动机：

1. 我一直想做一款自己的桌游，但「全栈 + 美术 + 音效」的个人成本太高，永远停在念头。
2. 我更好奇另一个问题：**当 AI Agent 能切换专家角色时，「一人 + 一 AI」能不能等价于一支小型工作室？** 我想用一次真实交付来验证。

于是我给自己设了约束：只做创意决策和最终拍板，其余交给 Agent。

## 三、核心方法论：把 AI 当「工作室」用，而不是当「写码工具」

绝大多数「AI 写游戏」的故事，本质是一个人用 Copilot 打字更快。我想验证的是另一回事——**让一个 Agent 承担整支团队的角色**，人退到「总监」位置。

具体到《烽决》，我把 8 条管线映射成 Agent 的「专家模式」：

| 工作室岗位 | Agent 承担的工作 | 交付物 |
|---|---|---|
| PM | 里程碑拆分、进度复盘、风险红线 | 进度文档、发布策略 |
| 前端 | Preact + TS + Vite 实现对战界面 | 可玩前端 |
| 后端 | Cloudflare Worker + Durable Objects 实时对战 | 联机服务 |
| 规则设计师 | 军棋变体规则引擎 + 单测 | 共享 TS 包 |
| 地图设计师 | 6×13 棋盘、河流 / 草丛 / 铁道 / 传送门 | 4 张地图 + 编辑器 |
| 美术 | 棋子 / 棋盘 / UI 贴图 | 173 张图（专属 worktree 并行） |
| 音效 | 30 个 wav 音效设计 | 音效包（专属 worktree 并行） |
| DevOps | CI/CD、Pages/Worker 部署、GitCode 镜像 | 自动部署流水线 |

关键不是「Agent 写了代码」，而是**角色之间的上下文由我统一掌管**——PM 视角定口径，前端 / 后端 / 规则共享同一份类型与数据契约，美术和音效并行在独立 worktree 里产出，最后由我终审合流。这恰恰是一家真实工作室的协作结构。

## 四、数据佐证（含诚实的坑）

讲漂亮话容易，难的是经得起扒。

- **代码量**：4 个代码仓库合计 130 次提交、约 1.5 万行（含配置），其中近 1 万行核心源码。全程 Conventional Commits。
- **测试**：规则引擎 74 个单元测试全绿（vitest 实跑）；服务端有测试文件；**前端目前 0 自动化测试**——这部分靠手测 + 线上 E2E 兜底，是我自己要补的债。
- **实测对局**：早期内部对战因一个 bug（炸弹结算）没跑完，已修复，现在线上 E2E 已通过、可正常对局。

我把这些坑写进来，是因为「AI 工作室」的价值不在于它不出错，而在于**出错到修复的闭环极短**——一个 Agent 改完规则、跑通单测、重新部署，往往就在同一次对话里完成。

## 五、技术亮点速览

《烽决》只是从军棋借了点灵感，但内容和军棋千差万别；真要说像什么，这棋盘看起来反而更接近斗兽棋。我真正做的，是下面这几个自己的机制：

- **6×13 棋盘**，河流 / 草丛 / 陷阱 / 基地四种地形；草丛里撞见对手会触发「同归于尽」式的暗战。
- **铁道滑行 + 传送门**：棋子可沿铁路快速机动，传送门支持链式跳跃——这是规则引擎里最烧脑也最好玩的部分。
- **假基地机制**：基地区可以放不可移动的「诱饵」棋子，迷惑对手的判断。
- **暗棋揭示（5 级）**：联机时双方信息不完全公开，靠对局推进逐步揭示——这直接决定了后端要做**信息隐藏 + 实时仲裁**（Durable Objects 负责房间与权威状态）。
- **联网架构**：Cloudflare Worker + Durable Objects 做实时对战房间，D1 存战绩、R2 存棋谱，KV 做会话缓存。一套 Serverless 全栈，零运维。

- 👉 试玩入口：[duel.tmoc.qzz.io](https://duel.tmoc.qzz.io)

如果你试玩后发现某个机制太强 / 太弱，欢迎来告诉我——这游戏的规则引擎是参数化的，调整平衡性对 Agent 来说只是改一份配置。

## 七、你可以抄走的「AI 工作室」工作流

如果也想试一次「一人 + 一 AI 造点东西」，我的几条经验：

1. **你只做创意总监 + 终审**：把「要什么」说清楚，把「怎么做」交给 Agent 的专家模式。
2. **用仓库 / 文档做「共享记忆」**：PM 视角的进度文档、数据清单、发布策略，是让 Agent 在多轮对话里不丢失上下文的关键。
3. **重资产（美术 / 音效）走并行 worktree**：不阻塞主线，最后合流。
4. **CI/CD 门禁保底**：规则引擎单测、自动部署，让「改完即上线」可信。
5. **诚实标注 alpha**：别用「完成」骗自己，也骗不了读者。
