`lp-toys` 这个仓装了两个说不清用途的小东西：

```
鼠标跟随.e          7,211 字节   2016-04-07
用热键来整人.e      7,998 字节   2017-12-10
```

两个都没有编入第三方模块，扫描产出分别是 **66 条**和 **32 条**。小到不需要任何筛选技巧 —— 直接全贴出来读。方法本身在[旗舰篇](/posts/2026-10-17-epl-e-container-reading/)，这篇的重点是**这套方法的天花板在哪**。

程序意图完全透明：

- `添加图片`（按钮1）→ `通用对话框1` 选文件 → 存进 `图片组`（记住 `路径`、`标识值`）
- `开始跟随`（按钮2）/ `停止跟随`（按钮3）控制 `时钟1`
- `_时钟1_周期事件` 里读 `鼠标水平位置` / `鼠标垂直位置`，把 `执行图片` 画到 `动画框1` 上
- `__启动窗口_尺寸被改变` 让动画框跟着窗口缩放
- `_动画框1_动画框鼠标位置改变` + `横坐标` / `纵坐标` / `已被按下物体` 是动画框自己的交互事件

两份清单我都按长度前缀截干净了。原始输出里还带着[远程控制那篇](/posts/2026-10-17-epl-remote-control/)说的 1–3 字节越界伪影 —— 比如这里实际扫到的是 `系统核心支持库;`、`扩展界面支持库二9`、`多线程支持库8`，末尾那个字符属于下一条记录。

一个"自定义光标"玩具。用的是**扩展界面支持库二**（`动画框` 只在这个库里），所以它必须挂这个库 —— 这类"控件名 → 属于哪个支持库"的对应关系，扫一遍就能反过来确认我没读错。

## 那个 `*.GMP`

```
图片格式(*.JPG;*.GMP)
```

`GMP` 不是任何图像格式。应该是 `GIF` 打错了 —— 而 `*.JPG` 也写成大写在易语言的过滤器里很常见（它按字面显示，不影响匹配）。

这种小错是最能证明"这真是我自己写的"的东西。我留着它，没改。

# 二、用热键来整人.e：能枚举，不等于能读懂

这个程序的**全部**扫描产出：

```

   493  在程序启动后自动调入本窗口
   778  标签1
  1022  d09f2340818511d396f6aaf844c7e325     ← 系统核心支持库 GUID

  1085  DA19AC3ADD2F4121AAD84AC5FBCAFC71     ← shellEx 的 GUID
  1122  扩展功能支持库一

  3358  _标签1_反馈事件                      ← 唯一的事件处理函数

```

窗口上没有按钮、没有编辑框，只有一个 `标签1`。界面几乎是空的 —— 它不需要界面。

## 读得出的行为画像

四条独立证据，可以拼出一个完整功能：

| 证据 | 含义 |
|---|---|
| `shutdown /s /t 60` | 60 秒后关机。倒计时留了 60 秒，是给受害者抢救用的 |
| `shutdown /a` | 取消关机 —— 程序知道怎么撤销自己干的事 |
| `shellEx` 支持库 | 扫到的配对是 `shellEx` ↔ `扩展功能支持库一`（内核名和显示名挨着存），这个库提供的就是执行 shell 命令的能力，两条 `shutdown` 都走它 |
| `software\microsoft\windows\CurrentVersion\Run\UseHotKeyHaveFun` | 注册表 Run 项自启动，值名直译"用热键找乐子" |
| `C:\1.exe` | 自启动项要指向一个稳定路径 —— 它把自己复制到 `C:\1.exe` |
| `Locked` / `ShutDown` | 两条常量名，挨着存，后面还有 `BY` / `a` / `b`。从字面看像两种玩法的名字，但值没读出来 |

**这就是 2017 年的我对"持久化"的全部理解**：复制到 C 盘根目录、起名 `1.exe`、写 Run 键。手法完全正确，也完全没必要 —— 一个整人程序根本不需要重启后还在。当时大概是觉得"隐藏自己"很帅。

## 读不出的部分

**这个程序的核心是热键，而容器里没有任何一条字符串和热键有关。**

没有 `RegisterHotKey`，没有虚拟键码，没有修饰键常量，没有任何形如 `Ctrl+Alt+Del` 的文本。能看到的只有事件名 `_标签1_反馈事件`（带 `参数一`、`参数二`）—— 而 `反馈事件` 这个事件名，我在易语言标准 `标签` 组件的事件表里对不上号，它八成来自 `扩展功能支持库一`，但我无法确认到底是哪个组件提供了它。

也就是说：

- **它绑了什么组合键** —— 读不出来
- **回调里做了什么判断**（比如累计按了几次才关机） —— 读不出来
- **`Locked` 和 `ShutDown` 这两个常量各自的值** —— 名字读到了，值没读出来

这就是字节扫描的下界。32 条串我全都有，一个不漏，**它们仍然不构成程序的行为**。窗体名给出界面、字符串常量给出文案和命令、支持库名给出能力边界 —— 这三样凑齐了，"程序做什么"能猜个八九分；但"程序什么时候做、对谁做、做完怎么判断"是控制流，控制流在二进制记录里，扫不出来。

想补上这一段只有两条路：装 IDE，或者拿 `shutdown` 下断点去 x64dbg 里跟 —— 而为了一个 8 KB 的整人程序做这两件事，不值当。

**所以我没有补。** 我把"读不出来"原样写在这里，这比硬凑一段"它是这样工作的"要诚实，信息量也更大 —— 因为它告诉读者这套方法真实的适用范围。

# 为什么这两个合在一个仓里

两个都是不到 100 条串的小东西，各开一个仓没意义。而且它们唯一的共同点就是"做完就为了给人看两秒"。

发它们的理由也不是技术，是那两个文件名。`鼠标跟随` 和 `用热键来整人` —— 一个 2016 年，一个 2017 年，中间隔着我做聊天器和机器人的那段时间。那阵子我写代码的全部动机是"我想让屏幕上出现一个不该出现的东西"。这个动机后来没再出现过，值得留个证据。

（QQ 号我这次统一抹掉了 —— 容器抹了，正文里也不再印一遍。同系列的[远程控制](/posts/2026-10-17-epl-remote-control/)那篇里，标题尾巴上的 `by…` 同样是打码后的形状。）
